# ドリフト推定モデルの独立校正と未使用データでの自動選択

単一路・二経路の両モデルで共通周波数変化率を推定する処理に、新しい校正閾値を適用した。前回の開発データ再生から進め、校正用と評価用を分離して自動モデル選択を検証する。

## 実験前に固定した条件

- 推定器は `drift_carrier_paths_cpu.py` を変更せず利用。800 ms、PRN1、白色雑音37 reference dB-Hz、片側帯域3.6828 MHz。
- 共通周波数変化率は一様分布[-2,2] Hz/秒、初期共通周波数は独立な一様分布[-1,1] Hz。観測ごとに新しく生成する。
- 反射ありの条件は電圧比0.8、超過遅延0.1 chip、相対Doppler+0.1 Hz、初期相対位相180度。
- 校正は新規の反射なし299例（ID980000〜）。評価は別の反射なし64例（ID990000〜）と反射あり32例（ID1000000〜）。以前の開発データともIDを重複させない。
- 真のドリフト・周波数・遅延・経路数は推定器に渡さない。両モデルを推定してから、スコアと局所ガードだけで選択する。

実行前に全タスク・ソースハッシュ・評価方針をprotocol.jsonへ保存。校正を完了し閾値を保存してから、初めて評価用データを処理する。旧閾値を流用せず、結果を見た閾値の再調整もしない。

## 校正と選択の意味

雑音重みの推定を含む全工程に対し、校正スコアの最大値を閾値とする。独立同分布の反射なし標本299例を使うと、閾値の真の超過確率が1%を超える校正失敗確率は .99^299<5%で抑えられる。

これは指定した**ドリフト・周波数・遅延・位相・雑音の生成分布全体で平均した保証**である。各変化率で1%以下という保証でも、範囲内の最悪条件に対する保証でもない。異なる雑音分布、信号強度、観測時間にはそのまま適用できない。

閾値以下なら局所ガードを通った単一路、超過なら同じく二経路を選ぶ。要求された推定が局所的に利用不能ならambiguousを返し、別モデルへフォールバックしない。二経路の最終選択はスコア超過の部分集合なので、反射なしの誤選択にも同じ校正上界が適用される。

距離成功は絶対誤差10 m未満で利用不能を失敗に含める。生成時の経路数を使う診断は参考として別に保存する。正確95%区間は集計ごとの点別区間で、同時区間ではない。旧受信機との有意な優越性を検定する実験ではなく、モデル変更と校正分布変更の効果も分離していない。

## 結果

新しく凍結した閾値は **−27.762974167383057**。

| 未使用信号 | 件数 | スコア超過 | 二経路選択 | 利用不能 | 距離誤差10 m未満 | 既知経路数の距離成功 |
|---|---:|---:|---:|---:|---:|---:|
| 反射なし | 64 | 0 | 0（偽検出） | 0 | 64 | 64 |
| 反射あり | 32 | 32 | 31 | 1 | 31 | 31 |

反射なしの偽検出率は観測上0/64、点別正確95%区間は **0〜5.60%**。この評価標本だけで真の誤検出率1%以下を証明したわけではない。前述の校正上界と評価標本の区間推定は別の主張である。

反射ありの二経路選択と距離成功はともに31/32（96.875%、点別正確95%区間83.78〜99.92%）。全32例のスコアは閾値を超え、1例だけ二経路推定の局所ガードで利用不能となった。自動選択によって既知経路数の距離成功を失った例は今回0件だった。

残った失敗はreplica **1000027**、真の変化率−1.59083 Hz/秒、初期周波数+0.95974 Hz。スコア+543.27は十分高いが、推定超過遅延が0.01 chipの下限に達した。推定は収束しており、局所遅延標準偏差も0.10423 chipで0.1 chipのガードを超えている。単に閾値や境界ガードを緩めて回復扱いにはできない。

既知経路数での変化率の平均絶対誤差は反射なし0.0641 Hz/秒、反射あり0.1314 Hz/秒。後者には利用不能例の推定値も含む記述統計で、誤差保証ではない。

ドリフト推定を含む新モデルで独立校正と未使用データの自動選択まで完了した。今回の分布では以前のような大量の偽二経路選択は観測されなかった。ただし以前とは校正分布・評価データも異なるため、モデル変更だけの因果効果や統計的な優越性を主張しない。

残る課題は逆位相の近接経路で境界に達する例と、反射条件・雑音・位相変化モデルが異なる場合の頑健性である。また現実的な利用に向けて、CPU上の多開始点探索の計算量も削減する必要がある。高速化する場合は数値結果の同等性を確認し、推定挙動が変わる変更には再校正が必要となる。

## 検証・再現

新しいDriftFitが既存の厳密閾値・局所ガード規則に従うこと、生成時の真値を変えても選択結果が変わらないこと、正負の混合分布の再現性とID非重複を確認。推定器の勾配・復元テストと合わせて8テストが成功した。監査では全ソースハッシュ、開発・校正・評価IDの非重複、閾値の再計算、全96判定と集計を確認した。校正2例・評価4例のフル再実行も完全一致した。

```bash
source /workspace/.gnss-env/activate.sh
pytest -q tests/test_drift_selection.py tests/test_drift_carrier_paths_cpu.py
# Requires an empty output/cpu-drift-selection directory
python -m experiments.run_cpu_drift_selection
python -m experiments.audit_cpu_drift_selection
python -m experiments.plot_cpu_drift_selection
```

成果物は `output/cpu-drift-selection/` のprotocol.json、calibration.jsonl、frozen_gate.json、evaluation.jsonl、report.json、completion.json、audit.json、comparison.png/pdf。

共通線形ドリフトと固定コード遅延の合成モデルであり、実測RF、追尾ループ、ナビゲーションビット、確率的位相雑音、森林・雨、複数衛星PVTは未検証。
