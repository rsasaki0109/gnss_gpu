# 観測時間を延ばした逆位相二経路の推定診断

200 msで逆位相の経路分離が不安定だった問題に対し、観測を400/800 msに延ばす実験を追加した。新しい合成信号を使用し、同じ800 ms観測の先頭部分を切り出して比較する。経路数は集計時に既知とする診断であり、自動検出性能の検証ではない。

## 実装と条件

`duration_carrier_paths_cpu.py` は凍結済み共通搬送波推定器を別ファイルに複製し、時間係数と入力ブロック数を10/20/40個に一般化した。各ブロックは20 ms。200 msの場合は従来の時間係数関数を直接使い、推定結果を完全一致させる。

探索範囲、粗探索の格子、12開始点、最大250反復、局所ガードは従来と同じ。観測から残差PSDを推定して再推定する工程は時間ごとに実行する。単一路・二経路の両推定を真値を渡さずに実行し、診断の距離成功には二経路推定を使用する。時間ごとのスコアは保存するが、旧閾値で自動選択しない。

- PRN1、白色雑音37 reference dB-Hz、片側帯域3.6828 MHz。
- 反射電圧比0.8、超過遅延0.1 chip、初期相対位相180度。
- 共通搬送波は一様分布[-1,1] Hz。相対Dopplerは0/0.1/0.7 Hz。
- 新しい8乱数ID900000〜を全時間・全Doppler条件で共有。全9条件72推定。
- 雑音は800 ms全体を一度生成し、200/400 msはその完全一致する先頭部分を使用。観測時間あたりのC/N0は固定され、長時間ほど総観測エネルギーは増える。

距離成功は絶対誤差10 m未満、利用不能を失敗として含める。8個の共有乱数を独立な72標本とみなさない。事前に全タスクとソースハッシュを保存した探索的な比較であり、有意差検定は行わない。

## 結果

各欄は8例中の距離成功数（絶対誤差10 m未満）。

| 相対Doppler Hz | 200 ms | 400 ms | 800 ms |
|---:|---:|---:|---:|
| 0 | 4 | 5 | 8 |
| 0.1 | 5 | 6 | 8 |
| 0.7 | 7 | 8 | 8 |

利用不能数はそれぞれ0 Hzで4→3→0、0.1 Hzで3→2→0、0.7 Hzで1→0→0。今回、利用可能と判定された全例は距離成功だった。200 ms・0 Hzの利用不能4例の内訳は探索境界3例と局所情報不足1例。その他の利用不能はすべて探索境界であり、最適化の未収束は全72推定で0件だった。

200 msとの対応比較では、800 msで新たに成功した件数が0 Hzで4例、0.1 Hzで3例、0.7 Hzで1例。成功から失敗に変わった例はなかった。共有乱数を使った少数例の探索であり、有意な改善の証明ではない。8/8成功でも成功率の点別正確95%下限は約63.1%である。

相対Doppler0 Hzでも改善が見られたため、今回の改善を「反射位相が時間変化した効果だけ」とは説明できない。一方、長時間化による雑音平均化・重み推定の変化・最適化の挙動は切り分けていない。

境界を緩める診断では回復できなかった問題に対し、観測時間の延長は今回の新規データで改善候補になった。過去の失敗13観測そのものを延長した結果ではなく、同じ反射条件の新規8例を使った比較である。

次は別の乱数とより多くの標本で再現性を確認し、長い積分時間での位相ずれやビット遷移など、理想的な位相整合が崩れた場合を検証する必要がある。自動選択の校正前に、既知経路数での成功数をそのまま受信機の検出性能として扱わない。

## 解釈の制約

長時間化は総エネルギーと相対位相の時間変化を同時に増やす。この実験だけで両者の効果を分離することはできない。相対Doppler0の場合は相対位相が一定であり、非ゼロの場合は観測中に変化する。

全800 msで完全にコヒーレントな信号を仮定する。ナビゲーションビット遷移、発振器ドリフト、追尾ループ、時間変化する反射振幅・コード遅延、実測雑音は含まない。長時間ほど実機でのこの仮定は厳しくなる。

粗探索格子は時間に合わせて細かくしていない。長時間化で目的関数の局所解が増える可能性があり、成績の変化をすべて情報量の変化だけに帰属させない。今回の条件で自動判定へ進むには、時間ごとの新しい独立校正が必要。

## 検証・再現

200 msでの従来推定器との完全一致、200/400 msと800 ms先頭部分の完全一致、400/800 msでの解析勾配と有限差分、分離内積と明示的残差の一致、時間係数の微分、不正なブロック数の拒否を確認した。既存推定器と合わせて10テストが成功。監査では全72件のタスクと集計、ソースハッシュ、過去データとのID非重複、各時間での先頭200 msの信号ハッシュ一致を確認した。全9条件から各1例をフル再実行し、完全一致した。

```bash
source /workspace/.gnss-env/activate.sh
pytest -q tests/test_carrier_duration.py tests/test_common_carrier_paths_cpu.py
# Requires an empty output/cpu-carrier-duration directory
python -m experiments.run_cpu_carrier_duration
python -m experiments.audit_cpu_carrier_duration
python -m experiments.plot_cpu_carrier_duration
```

成果物は `output/cpu-carrier-duration/` のprotocol.json、evaluation.jsonl、report.json、completion.json、audit.json、comparison.png/pdf。距離推定の診断であり、複数衛星の測位や森林・雨に対する検証ではない。
