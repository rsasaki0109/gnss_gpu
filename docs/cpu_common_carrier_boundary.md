# 共通搬送波モデル：逆位相での境界解の診断

逆位相条件で利用不能となった全13観測を診断した。探索開始点を増やしても、元と同じ探索範囲では実質的に小さい残差の解は見つからなかった。超過遅延の下限を0.01から0.001 chipに下げると、全例が新しい下限へ移動し、残差のわずかな減少と引き換えに局所遅延不確かさが約10倍に増えた。

この結果は「下限を緩めれば距離推定を回復できる」という説明を支持しない。近接した二つの大きな経路成分が打ち消し合う、識別しにくい解と整合する。ただし、有限の多開始点探索で大域最適性を証明したものではない。

## 対象と手順

`cpu-common-carrier-phase-stress` の全176観測から、選択がambiguousかつ理由がsearch boundaryだった全13件を採用した。初期位相はすべて180度。相対Doppler0 Hzが5件、0.1 Hzが6件、0.7 Hzが2件。共有乱数による同一replicaの別条件を含むため、13件を独立な母集団標本とは扱わない。

1. 元の信号と予備推定から雑音重みを再生成し、両方のSHA256が保存値と完全一致することを確認。
2. 重みを固定したまま、明示的な全設計行列と複素最小二乗から残差を計算。受信処理の時間・周波数分離内積による計算と照合。
3. 遅延25点×共通搬送波3点×超過遅延5点×相対Doppler9点の粗探索から上位32開始点と元の推定点を選び、各点最大400反復で最適化。
4. 元と同じ下限0.01 chip、および下限だけ0.001 chipへ緩和した場合を比較。元の解は常に候補に残し、明示的な最小二乗残差が最小の候補を記録。

相対残差減少が1e-9を超える場合を実質的な変化とする基準を、診断前のprotocol.jsonに記載した。診断は受信処理・閾値の変更ではなく、得た最小残差解を距離出力として採用しない。

## 結果

| 指標 | 元と同じ下限・開始点増加 | 下限0.001 chip |
|---|---:|---:|
| 実質的に残差が小さくなった件数 | 0/13 | 13/13 |
| 超過遅延が下限に達した件数 | 13/13 | 13/13 |
| 局所遅延標準偏差が0.1 chipを超えた件数 | 13/13 | 13/13 |
| 局所遅延標準偏差の範囲 chip | 0.154〜0.265 | 1.553〜2.675 |
| 打ち消し比の範囲 | 27.7〜45.8 | 276.8〜457.9 |
| 設計行列の条件数の範囲 | 40.3〜51.5 | 402.6〜514.4 |
| 最大相対残差減少 | 2.10e-15 | 1.33e-7 |
| 最小残差候補の未収束 | 1/13 | 0/13 |

打ち消し比は「推定した各経路の重み付き信号ノルムの和 ÷ 合成予測信号のノルム」。値が大きいほど、大きな成分同士が強く相殺して合成信号を作る。

元の解での明示的最小二乗残差と分離内積実装の明示的残差の差は最大4.55e-12。元と同じ下限の比較では数値丸め程度しか残差が変わらず、最小候補に未収束1件が含まれる。収束状態は隠さず記録し、この候補を改善解とは扱わない。

例としてreplica 880004・相対Doppler0 Hzでは、残差平方和が6928.434312から6928.433493へわずかに減少する一方、局所標準偏差は0.265から2.675 chip、打ち消し比は44.8から447.5へ増大した。距離誤差も+16.39から+17.70 mとなった。

全13観測で、下限を緩和した候補の距離誤差は+10.25〜+17.70 m。局所ガードを無視しても、この診断では10 m未満の回復は得られていない。元の解でも全13例が局所標準偏差ガードを超えており、境界ガードだけを外しても受信処理上は利用不能のままである。

## 限界と次の候補

これは過去の失敗例を選んだ事後診断であり、受信機全体の成功率や失敗確率の推定ではない。雑音重みを固定しているため、重みの再推定と最適化を繰り返す別工程の効果も検証していない。

次は、観測時間を延ばすなど、経路識別の情報を増やす条件を調べるのが候補になる。あるいは振幅や遅延に物理的な制約を導入する場合、その仮定が実際の反射に適用できる根拠が必要。どちらも推定工程が変わるため、既存の閾値を流用せず独立校正と未使用データ評価が必要になる。

単に探索境界を緩めたり、推定に都合のよい真値制約を追加したりして「回復」とはしない。今回の診断から、全条件での情報不足や大域的最適解を断定することもできない。

## 検証・再現

診断用の明示的残差と分離内積の一致を、超過遅延0.001/0.01/0.1 chipで確認。対象選択のテストと既存推定器テストを合わせて9件が成功した。監査では全13対象の網羅、固定ソース・元成果物、信号と重みのハッシュ、集計再計算を確認し、2観測の診断全体を再実行して完全一致した。

```bash
source /workspace/.gnss-env/activate.sh
pytest -q tests/test_common_carrier_boundary.py tests/test_common_carrier_paths_cpu.py
# Requires an empty output/cpu-common-carrier-boundary directory
python -m experiments.diagnose_cpu_common_carrier_boundary
python -m experiments.audit_cpu_common_carrier_boundary
python -m experiments.plot_cpu_common_carrier_boundary
```

成果物は `output/cpu-common-carrier-boundary/` のprotocol.json、diagnostics.jsonl、report.json、completion.json、audit.json、comparison.png/pdf。
