# ドリフト推定器のCPU高速化：遅延テンプレートと観測投影の再利用

周波数ドリフト推定器の探索条件を変えずに、同じ遅延に対する繰り返し計算を削減した。凍結済みの `drift_carrier_paths_cpu.py` は保持し、`cached_drift_carrier_paths_cpu.py` に高速化版を追加した。

## 測定から選んだ変更

既存の反射なし評価例1件をcProfileで測定すると、全工程約11.65秒のうち約8.10秒が、観測とテンプレートの相関関数に集積していた。このプロファイルは計測オーバーヘッドを含む原因調査で、速度比較の数値には使わない。詳細は `output/cpu-drift-cache-profile/baseline.txt` とbaseline.profに保存。

観測yと重み付き周波数テンプレートv(delay)が同じなら、y @ conj(v)は搬送波周波数やドリフトが変わっても同じである。この計算は時間係数との内積の前段にあり、粗探索や勾配計算で何度も繰り返されていた。

高速化版は各問題（特定の観測・雑音重み）に閉じた64エントリーのLRUキャッシュを持ち、次を保存する。

- 正確な浮動小数点の遅延をキーにしたテンプレートv。
- その遅延微分slope*v。
- 観測との二つの投影y @ conj(v)、y @ conj(slope*v)。

遅延値は丸めず、近い値を同一視しない。観測や雑音重みをまたいでキャッシュを共有しない。探索格子、開始点、反復上限、勾配の数式、局所ガード、スコア、判定閾値は変更しない。

800 msの場合、64エントリーの配列本体は1問題あたり約15.2 MB。Python管理情報、観測配列、最適化・行列演算用メモリは別で、ピークRSSの実測値ではない。計算削減と引き換えに、この追加メモリを使う。

## 比較方法

直近の `cpu-drift-selection` の校正先頭例、反射なし評価先頭例、反射あり評価先頭例、残った探索境界失敗例を事前選択。全4例で2回ずつ、計8組の同一観測による時間比較を行う。

同じホスト・同じPythonプロセスで両実装を事前に1回ウォームアップし、各組では旧→新と新→旧を交互に実行する。時間は推定工程全体の実時間で、信号生成・インポート・結果照合を除く。BLASは1スレッド。小規模なローカル測定であり、他の機器やすべての信号で同じ倍率を保証しない。

さらに、保存済み校正299例と評価96例の**全395観測**を高速化版で再実行する。許容誤差による比較ではなく、全推定フィールド、スコア、雑音重み配列のバイト列が既存結果と完全一致することを要求する。以前の閾値を保持して全96判定と集計も再計算する。並列再実行の所要時間は速度比較に混ぜない。

## 結果

| 指標 | 結果 |
|---|---:|
| 旧実装の全工程時間中央値 | 10.691秒 |
| 高速化版の全工程時間中央値 | 2.397秒 |
| 各組の速度比の中央値 | **4.489倍** |
| 各組の速度比の範囲 | 4.334〜4.820倍 |
| 校正観測の完全一致 | **299/299** |
| 評価観測の完全一致 | **96/96** |
| 元の評価判定・集計 | 全件一致 |

速度比は各組で「旧時間÷新時間」を計算してから中央値を取ったもの。両実装の時間中央値の比とは計算方法が異なる。4観測×2反復という小規模な同一ホストの測定であり、普遍的な速度向上率の推定ではない。

校正と評価の全395観測で、すべての推定フィールド、スコア、雑音重みのバイト列が一致した。元の校正閾値−27.762974167383057を保持し、反射なし誤検出0/64・距離成功64/64、反射あり二経路選択31/32・距離成功31/32という結果も変わらない。残った探索境界の利用不能例もそのまま再現した。

この変更はモデルや推論方法の改善ではなく、同じ処理の重複計算を省く高速化である。今回の395入力で校正結果を保持できることは確認したが、別の数値環境まで無条件に同じ閾値を適用できるという主張ではない。

## 検証・再現

64件を超える異なる遅延によるキャッシュ追い出し、単一路・二経路の目的関数と解析勾配、明示的設計行列、異なる観測・重みとの分離、全工程の完全一致を確認する3テストが成功。監査では元の成果物・全ソースのハッシュ、395件の対応、8組の計時記録を確認し、さらに6例を高速化版でフル再実行して一致を確認した。

```bash
source /workspace/.gnss-env/activate.sh
pytest -q tests/test_cached_drift_paths.py
# Requires an empty output/cpu-drift-cache-benchmark directory
python -m experiments.benchmark_cpu_drift_cache
python -m experiments.audit_cpu_drift_cache
python -m experiments.plot_cpu_drift_cache
```

成果物は `output/cpu-drift-cache-benchmark/` のprotocol.json、timings.jsonl、replay.jsonl、report.json、completion.json、audit.json、comparison.png/pdf。既存の受信処理と過去の実験ファイルは置き換えていない。

高速化版を新しい実験で使用する場合は、`gnss_gpu.cached_drift_carrier_paths_cpu.score_drift_paths` をインポートする。今回の一致は確認した入力・数値環境に対する実測結果であり、任意の入力や別BLAS実装まで同等性を数学的に証明したものではない。研究成果の信号モデル上の制約や、実機・測位への未検証範囲は変わらない。
