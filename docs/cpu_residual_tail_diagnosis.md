# 帰無校正の大きいスコアを診断

前回の最大値ゲートを押し上げた校正ケースは、独立な残差計算と探索初期値の増加でも再現した。真の雑音PSDを使っても大きいスコアが残り、今回調べた範囲では除外すべき計算ミスは見つからなかった。帰無分布の裾で起きた観測として保持し、ゲートや過去の結果は変更していない。

## 対象と診断方法

`output/cpu-residual-ranked/calibration.jsonl` の各分布640件から、スコア順位1・2・3・320位を選び、計12件を診断した。既知の結果を選んだ事後診断であり、新しい性能検証ではない。選択規則・ケースID・ソース・過去の出力ハッシュを診断前に保存。

- 元の観測と残差重みを再生成し、保存済みハッシュとの完全一致を確認。
- 時間と周波数に分けたGram行列の計算とは別に、10×7365観測を並べた全設計行列を作り、`lstsq`で複素振幅と残差を再計算。
- 雑音重みを固定し、1経路は遅延641点から上位16近傍を再最適化。2経路は25×5×9の粗探索から32初期値と元の推定値を使い、最大400反復で再探索。
- 診断専用に、生成時の真の相対雑音PSDを使ったフィットも比較。これは推定器が利用できる情報ではなく、実装への真値投入や校正済みの方式変更ではない。

損失の相対改善1e-9超を実質的な差として集計する。多初期値の局所探索であり、大域最適性は保証しない。初期の雑音推定用フィット自体を全探索したものでもない。

## 数値再現の結果

12件の元のスコアと全設計行列で再計算したスコアの最大差は **3.27e-11**。探索初期値を増やした後の最大スコア変化は **3.93e-10**。1経路・2経路とも実質的に小さい損失は0/12件で、拡張探索の最良候補は全件が収束を報告した。

閾値を決めたedge・replica 682404の結果：

| 診断 | スコア |
|---|---:|
| 元の残差重み付き推定 | -6.327790688 |
| 全設計行列による再計算 | -6.327790688 |
| 同じ重みで初期値を増やす | -6.327790688 |
| 真の雑音PSDで推定 | -5.623182876 |

このケースの相対雑音分布推定RMS誤差は約3.17%、推定した2経路の設計行列条件数は約1.086で、局所ガードも通過していた。真のPSDでもスコアはむしろ少し高いため、雑音分布推定の誤差だけでは大きいスコアを説明できない。以前の「経路が密着して巨大な振幅同士が打ち消す」境界ケースとも、今回の条件数は異なる。

この観測は反射なしの生成モデルから再現されている。ただし有限の選択済み12件から帰無分布全体の形や発生頻度を証明したわけではない。最大値方式を都合よく改善するために、このケースを校正から削除しない。

## 真のPSDを使う診断で見つかった局所解

center・replica 681139（順位3）は、真のPSDで通常の初期値選択を使うとスコア -37.244838 になった。一見、元の -26.611213 との差が雑音重みの誤差に見える。しかし、元の推定位置を真のPSD用探索の追加初期値として与えると、収束済みのより小さい損失が見つかり、スコアは **-26.891861** になった。

したがって、この大きい差を雑音PSD推定の影響とみなすのは不適切。真のPSDを使う診断にも局所解の問題があることが分かった。追加初期値の確認は全12件に行い、1e-4を超えるスコア改善はこの1件だけだった。これは診断用の真値重みのフィットで見つかった問題で、現在の残差重み付き推定器の12件の結果を修正する証拠ではない。

追加診断は別ファイル `oracle_seed_check.json` に保存し、元の診断結果を上書きしていない。図は追加初期値で確認した真PSD側の最良スコアを表示する。両者とも大域最適を保証しない。

## 検証と今後

新規2テストと既存の残差推定5テスト、計7テスト成功。全設計行列とGram行列の損失一致を近接経路も含めて確認。監査では12ケースの選択・固定ソースと過去出力・集計を再確認し、各分布の最大スコア3ケースを完全再実行した。追加診断はソース・入力ハッシュ、12件の対応、真PSDの通常フィットの全件再現を確認した。

この結果から、最大値ゲートの変動を計算ミスとして片付けられない。次は独立した校正実現で順位ゲートの変動を測ることが必要。また、真値を使わずに探索初期値を補強する場合も、独立したデータで数値的な改善と経路誤検出への影響を評価し、処理を変えるなら再校正する。

```bash
source /workspace/.gnss-env/activate.sh
pytest -q tests/test_residual_tail_diagnosis.py tests/test_residual_dynamic_paths_cpu.py
# 診断・追加診断は既存出力を上書きしない

python experiments/audit_cpu_residual_tail.py
python experiments/check_cpu_oracle_tail_seeds.py
python experiments/plot_cpu_residual_tail.py
```

出力は `output/cpu-residual-tail-diagnosis/`。今回の作業は事後診断の追加であり、受信機・校正閾値・既存の評価結果は変更していない。
